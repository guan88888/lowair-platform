# 天穹智航后端并行开发提示词

## 使用方式

每个代码块是一项可独立分配给一个 AI 窗口的任务。为减少冲突，先完成“任务 0”，之后任务 1-10 可并行；“任务 9 钱包资金”应在交易和工作订单的核心数据模型稳定后接入真实资金动作。

前端请求基址为 `/api/v1`，客户端会把成功响应中的 `data` 字段自动拆出，因此 API 可以直接返回 JSON，或统一返回 `{ "data": ... }`。分页接口统一返回：`{ "items": [], "page": 1, "page_size": 20, "total": 0, "has_more": false }`。

所有任务共同遵守：

- 技术栈固定为 FastAPI + SQLAlchemy 2.0 + MySQL，沿用 `backend/app` 现有分层、JWT 与 `get_current_user`。
- 新路由必须在 `app/api/v1/router.py` 注册；新模型必须被 `app/db/init_db.py` 导入/建表；为请求和响应建立 Pydantic schema。
- 所有写接口验证登录、对象归属和角色权限；所有列表实现分页、输入校验和确定的排序；禁止只返回 mock 数据。
- 不修改前端路径或字段名，兼容 `frontend/低空经济/features/*/services/index.js` 已有调用；补充 pytest 或 FastAPI TestClient 测试。
- 对上传先实现安全的对象存储抽象（开发可本地目录），限制 MIME、大小、归属与私有访问；不得让前端直传任意服务器路径。
- 每个任务完成时运行后端测试、说明新增模型/路由、列出尚需第三方服务接入的能力。

## 任务 0：平台基础、角色和通用上传（必须优先）

```text
你在项目 backend 中实现可供其他业务域复用的平台基础能力。不得实现学考、工作、交易、社区等业务模型；只做基础设施。

现状：FastAPI + SQLAlchemy + MySQL，已有 users、JWT 登录与 get_current_user。前端 auth 状态需要 user 返回 roles、active_role、verification/verifications 等字段，但当前 UserResponse 不含这些字段。

实现目标：
1. 增加用户角色与认证申请模型：角色至少 personal/pilot/enterprise/institution；认证类型 personal/caac/enterprise/institution；状态 not_submitted/pending/approved/rejected/expired；保存申请材料、驳回原因、提交/审核/到期时间。
2. 扩展 /auth/me 和认证登录/注册响应，使其返回 id、phone、nickname、is_active、roles、active_role、verification（或 verifications）；保持旧字段兼容。
3. 实现 GET /profile 与 POST /profile/verifications/{type}。提交接口需校验类型、保存申请，返回状态；不能让客户端自行设置 approved。实现最小审核接口只给后续后台/管理员使用，并记录审计事件。
4. 增加通用 MediaAsset/Upload 模型与受保护上传服务。提供 POST /uploads（multipart 或预签名申请均可）和 GET /uploads/{id} 的受权访问方式；返回 id、url、name、mime_type、size、status。开发模式可保存到 backend/uploads，生产配置留出对象存储环境变量。
5. 加入通用审计日志表（actor、action、resource_type、resource_id、before/after、时间）及写操作助手。
6. 增加标准 API 错误格式、请求 ID 中间件（回传 X-Request-ID）、基础分页工具和权限依赖（require_role / require_verified）。

验收：注册、登录、/auth/me 兼容现有前端；普通用户无法伪造企业/机构/CAAC 审核通过；上传不能读取他人私有文件；pytest 覆盖权限拒绝与核心成功路径。
```

## 任务 1：首页、全局搜索与飞行服务

```text
在 backend 实现首页、跨域搜索和飞行服务 API。不要改认证、钱包、交易、学考、工作、社区、广告或 AI 模型。

前端契约来源：frontend/低空经济/features/home/services/index.js。

实现接口：
- GET /home/modules/{key}?city=：key 只允许 carousel、summary、entries、tasks、institutions、devices、rumors；返回 {items, meta}。内容应来自可管理的数据表或适配器，不能硬编码在路由函数。
- GET /home/dashboard?city=：首页汇总。
- GET /search?keyword=&category=全部|机构|岗位|任务|商品|内容&page=&page_size=：返回跨域规范结果（id/category/title/note/source/to），按相关度和更新时间排序。先对已有各域表做 UNION/适配；某域表尚不存在时安全跳过。
- GET /flight/conditions?city=：返回 city/status/statusTone/weather/reasons/risks/checklist/disclaimer/meta。适配气象/空域数据源，开发环境允许明确标记 demo/fallback，但绝不可给出“可起飞许可”结论。
- GET /flight/fields?city= 和 GET /flight/maintenance-services?city=：飞场与维修服务目录，返回 {items,meta}。
- GET /flight/airspace-notices：分页空域通告。

设计：为气象、空域、飞场建立 provider interface；缓存有 TTL、数据来源和更新时间；城市参数白名单/长度校验；风险和免责声明始终返回。为每个 endpoint 写测试，尤其测试搜索分页、未知模块和飞行免责声明。
```

## 任务 6：AI 助手会话与模型代理

```text
在 backend 实现 assistant 域。不要把模型 API Key 放到前端，不要实现本地规则回复；前端已经有 demo fallback，生产接口必须是真正的服务端会话代理。

前端契约：frontend/低空经济/features/assistant/services/index.js 与 services/protocol.mjs。

模型：AssistantConversation、AssistantMessage、AssistantRun、Citation/Source、用量和安全审计。每个会话只属于一个用户。

实现接口：
- GET /assistant/conversations；POST /assistant/conversations；GET/DELETE /assistant/conversations/{id}。
- POST /assistant/conversations/{id}/messages：输入 content/mode，返回 assistant message 或可轮询 run；支持 X-Request-ID/幂等键。
- DELETE /assistant/conversations/{id}/messages 清空会话。

响应兼容 protocol：conversation 含 id/title/mode/updated_at/messages；message 含 id/role/content/status/created_at/sources/error/request；429 必须带 Retry-After。增加每用户限流、最大输入长度、敏感信息提示、审计和失败重试策略。

设计可插拔 ModelProvider（环境变量配置）；模型不可用时返回明确 503，绝不返回伪造实时空域/气象/许可结论。对话中涉及空域、气象、紧急事件时附安全边界和官方来源/待核对标记。测试会话隔离、删除、限流、模型失败和安全响应。
```

## 收尾集成任务：统一页面数据 API 与回归

