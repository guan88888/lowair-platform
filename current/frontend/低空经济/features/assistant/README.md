# Drone assistant feature

- Routes: `pages/assistant/index`; `pages/academy/assistant` reuses the same independent agent page.
- Owned files: `features/assistant/**` and its thin route shell.
- API boundary: conversations, model proxy and citations belong in `services/`; model credentials must remain server-side. The browser never accepts or stores a model key.
- Live mode: set `VITE_ASSISTANT_LIVE=true` and configure the shared `VITE_API_BASE_URL`. The feature calls only the authenticated application backend under `/assistant`.
- Demo mode: when live mode is disabled, responses are generated by local scenario rules, explicitly quote the question, identify missing information and include safety boundaries. Up to 30 conversations are restored from device storage.

## Backend proxy contract

The adapter accepts either direct payloads or `{ data: ... }` envelopes and normalizes common `snake_case` or `camelCase` fields.

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/assistant/conversations` | List restorable conversations |
| `POST` | `/assistant/conversations` | Create `{ mode, title }` |
| `GET` | `/assistant/conversations/:id` | Restore messages and citations |
| `POST` | `/assistant/conversations/:id/messages` | Send `{ content, mode, client_message_id, context? }`; supports idempotency and returns a run |
| `GET` | `/assistant/conversations/:id/runs/:runId` | Poll an asynchronous generation (only required when message POST returns a pending run) |
| `GET` | `/assistant/conversations/:id/runs/:runId/events` | Optional SSE stream; emits `delta`, `status`, `message` and `error` events. The client falls back to the same run's polling endpoint if SSE is unavailable or interrupted. |
| `POST` | `/assistant/conversations/:id/runs/:runId/cancel` | Cancel provider work for an asynchronous generation |
| `DELETE` | `/assistant/conversations/:id/messages` | Clear one conversation |
| `DELETE` | `/assistant/conversations/:id` | Delete one conversation |

`mode` is one of `飞前检查`, `任务方案`, `设备诊断`, `学考答疑`. `context` only accepts user-entered `aircraft_model` (80 chars), `city` (80 chars) and `task` (500 chars). The proxy must ignore or reject precise location, credentials, flight logs and unrelated private data unless a separate informed upload flow is added.

Message results should contain `id`, `role`, `content`, `status`, `created_at` and optional `sources` or `citations`. A source can include `id`, `title`, `excerpt`, `url`, `kind` and `pending`.

Generation can return `{ message }` immediately or `{ run: { id, status, retry_after, message?, error? } }`, where status is `queued`, `running`, `completed`, `failed` or `cancelled`. For SSE, each event is a blank-line-delimited block with `event: <kind>` and `data: <JSON>` lines; a `delta` payload is `{ "delta": "..." }`, a terminal `message` payload is `{ "message": { ...message fields } }`, and `[DONE]` is only a transport marker, not a successful answer. The proxy must send a terminal message before closing the stream. Pending run IDs are retained locally so a reload can resume polling. The client renders deltas, falls back to polling after a stream interruption, honors `retry_after`, maps HTTP `429` to a visible countdown, and exposes failed generations for user-initiated retry. `client_message_id` must be an idempotency key so transport retries cannot duplicate a user turn.

The text chat endpoint must call a server-side text model proxy. An image/vision model is not a substitute for text chat: it may only be used by a separately authorized evidence flow, and its output must be converted to a normal server-side message with citations and safety labels. The browser never selects a provider, sees a model credential, or calls a provider URL directly.

## Reserved multimodal and human-support contracts

These endpoints are reserved interfaces, not implicit browser capabilities. Until a consented UI is enabled, the client must not send these payloads.

| Method | Path | Contract and boundary |
| --- | --- | --- |
| `POST` | `/assistant/conversations/:id/attachments` | Create an upload intent `{ kind: "reference_image" | "flight_log", filename, mime_type, size, consent_id }`; server authenticates owner, allowlists MIME/size, malware-scans, expires the one-time upload URL and returns no provider credential. Images are optional evidence only; do not infer identity, exact location or safety clearance. |
| `POST` | `/assistant/conversations/:id/attachments/:attachmentId/complete` | Complete and scan the upload, returning `{ id, status, redactions, expires_at }`. `flight_log` is disabled by default because logs can contain precise tracks, IDs and device metadata; enable only after explicit purpose/retention consent and strip unnecessary fields. |
| `POST` | `/assistant/conversations/:id/voice/transcriptions` | Upload one user-selected audio clip to the backend STT service; return `{ transcript, language, expires_at }` for user review. Never record ambient audio, auto-send the transcript, expose STT/model keys or use voice as an emergency channel. |
| `POST` | `/assistant/conversations/:id/handoffs` | Create `{ reason, summary, included_message_ids, consent_id }` and return `{ ticket_id, status }`. Require explicit confirmation, redact secrets and unnecessary personal data, authorize the receiving staff member, and never promise immediate rescue or regulatory approval. |

Attachment, voice and handoff failures must be safe public errors and must not leak raw provider responses, storage URLs beyond their expiry, logs, prompts or credentials. Emergency, injury, fire and loss-of-control situations remain an immediate safety-services workflow, not an automatic human handoff.

The backend must authenticate the user if required, authorize the conversation owner on every route, apply per-user and per-IP rate limits, retain provider credentials, validate citation URLs and map provider errors to safe public messages. It should reject unsupported context fields, minimize and expire retained conversation data, audit provider calls without prompt or token leakage, and enforce server-side safety instructions for high-risk flight questions. It should never return provider API keys, raw secrets or privileged system prompts. The client independently opens only `http(s)` citation URLs.
