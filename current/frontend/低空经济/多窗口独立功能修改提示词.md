# 低空经济 App：多窗口独立功能修改提示词

## 使用顺序

当前项目的大部分页面都通过 `components/PageScreen.vue` 渲染。多个窗口若直接同时修改它，必然产生冲突。因此先完成并合并 **提示词 0**，再将提示词 1 至 14 分给不同窗口或不同分支。每个窗口只修改其提示词列出的文件范围；不要修改其他业务域的页面、数据、样式或路由。

统一技术约束：项目为 uni-app + Vue 3；保留现有路由和五项 Tab Bar（首页、学考、工作、交易、社区）；使用 `utils/request.js` 和 `VITE_API_BASE_URL` 调用 API；不得将 API Key、管理员权限或支付密钥写入前端；所有网络状态需有加载、空态、错误和重试；完成后执行 `npm run build:h5`。演示数据必须显式标注“演示”，不可伪装为真实认证、资金、质检或区块链数据。

## 提示词 0：一次性页面解耦与功能目录

```text
你正在维护 uni-app Vue 3 项目 `<LOCAL_PROJECT_PATH>`。请先阅读 `pages.json`、`components/PageScreen.vue`、`components/AppPageShell.vue`、`data/page-data.js`。

目标：解除所有业务页对巨型 `components/PageScreen.vue` 的直接依赖，为后续多个开发窗口按业务域并行开发建立不会冲突的代码边界。保留全部 40 个现有路由、页面标题、底部五项 Tab Bar 和现有可用交互。

实施要求：
1. 新建 `features/` 目录，至少分为 `home`、`academy`、`work`、`market`、`community`、`profile`、`assistant`、`shared`。每个业务域自行拥有 `components/`、`services/`、`mock/` 或 `types/`（按实际需要创建）。
2. 将每个 `pages/<domain>/*.vue` 改造成只引入本业务域页面组件的薄路由页；例如首页相关页面只依赖 `features/home`，交易页面只依赖 `features/market`。禁止路由页继续把业务渲染交给 `PageScreen.vue`。
3. 抽取确实跨域的、无业务状态的能力到 `features/shared`：请求状态视图、空态、错误态、分页、确认弹窗、格式化工具。`AppPageShell.vue` 仍是唯一的 Tab Bar / 浮动 AI 入口所有者，避免复制底栏。
4. 原 `PageScreen.vue` 的内容按页面原功能迁移，迁移完成后删除其中不再使用的业务分支；不要丢失轮播、考试、商品、表单、评论、消息、主题、语言和拖拽 AI 入口等功能。
5. 各业务域的模拟数据从 `data/page-data.js` 拆到自己的 `features/<domain>/mock/`，避免未来多人同时编辑同一个大数据文件。若无法一次完全迁移，保留兼容导出，但写清楚迁移注释。
6. 为每一个业务域在 `features/<domain>/README.md` 写明：归属路由、允许修改的文件、依赖的 API 服务、当前仍是演示的能力。

限制：不要改变接口 Base URL、不要泄露任何用户提供过的密钥、不要更改 `pages.json` 中既有 path。不要进行视觉大改。

验收：40 个路由仍能打开；五个 Tab 页面底栏一致；浮动 AI 可拖拽并可进入 AI 页面；`npm run build:h5` 成功。最后汇报迁移后的文件归属和仍需迁移的遗留项。
```
